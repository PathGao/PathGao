# 原创讲解视频

适用于 agent 根据选题、文字或资料编写旁白，并通过 HyperFrames 制作画面的视频。全局约定见 [AGENTS.md](../AGENTS.md)，共用验收见 [制作规范](../制作规范.md)。已有视频加字幕走[视频翻译](视频翻译.md)，不自动重写原片结构。

## 默认选择与项目记录

- S1 声音：本人配音视频使用本地 Higgs TTS 3。原创讲解沿用已认可的本人声线（[按稿件选本人播音腔或本人口语腔](../asset/voices/personal/README.md#两个参考怎么选)）及[Higgs 配方](../asset/voices/personal/personal-higgs3.json)，不重复询问是否使用本人声线。用户本次指定其他声音或引擎时按要求执行，并记录选择。
- S2 字幕：每个新项目开始时询问“仅中文字幕，还是中英双语字幕？”。本次已明确或该项目已确认则沿用，不在续做、返工时重复询问。不能因为上一期选过某种语言就跳过新项目询问。
- S3 其他信息：沿用已知平台、画幅、时长和素材，只补问会影响制作的缺项。在项目说明记录这些信息、字幕选择、声线配方和发布授权范围。

## 制作顺序

1. 选题确定后立即并行收集素材：按来源拆给多个子代理同时找和整理素材（见下方[多子代理并行](#多子代理并行)），不先由主代理单线收集。根据选题核验核心事实，按下方“封面与标题先行”形成候选组合并确定本期方向，记录吸引观众点击的理由和片中兑现方式，再写脚本。脚本按“结论 → 按场景展开的问题 → 证据 → 使用方法 → 限制与最终选择”展开，章节导航和段内小问题分层，观众能知道当前在回答什么。整理正式名称与口播读法，写显示稿和必要的发音稿。写完自查开场：只听前 15 秒（约前 3–5 句），观众能说出本期结论；结论之前不放背景介绍、信息来源或单张截图细节，来源和人物说明放在结论之后。2026-11-06 URXR 一期初版以官网截图开场，用户要求改为先抛总结。
2. 画面预审：脚本审定后、配音前，用 `pipelines/personal-voice/estimate-timing` 按字数估算逐行时长（已有旧配音时复用相同句子的真实时长），按估算时间轴先搭出无声画面，底部临时显示该行旁白文字，交用户看结构、开场和镜头。用户确认后再配音；配音完成后用真实时间轴重排，删除临时文字。依据：2026-11-06 用户要求“先看新版再配音”，按此做法省掉一轮配音返工。
3. 主代理写完口播稿后，固定交一个子代理做[口语化与去 AI 味](#口语化与去-ai-味子代理)，主代理逐行核对事实后再交用户审稿（2026-11-07 用户要求沉淀为固定步骤）。本人配音按下方[旁白与口播](#旁白与口播)改写稿件，发音稿每行一个语义单元，逐行生成并拼成连续主旁白，再截取短试听。命令与检查见[本人配音入口](../pipelines/personal-voice/README.md)，引擎说明见[Higgs 管线](../pipelines/tts-higgs/README.md)。逐段复核不可省略，旧逐字处理坐标不能套到新音频。试听通过后用 `pipelines/personal-voice/tighten` 按语义层级重排留白（去掉每行自带的头尾静音，句间、章节间留白取 timing-policy.json），产出 timing.json 供画面与字幕对齐；成片音轨从 voice-raw-tight.wav 做后处理。本机同一时间只跑一个 Higgs 任务，配音入口会自动排队等待，不要手动并发或按进程名停别人的任务。
4. 先审定旁白，再确定字幕和画面时间。超时优先删冗余信息，不靠整体加速把过长稿件塞进固定时长。仅中文字幕依据最终中文旁白生成。中英双语先把最终中文显示稿译为英文，按对应语义配对，两种语言均跟最终旁白时间轴对齐。
5. 制作 HyperFrames 工程前读取 hyperframes 技能及所需领域技能，使用工作区 `tools/hyperframes/run` 或已经配置的项目 scripts。画面风格按[样式规范](../样式规范.md)选：纯生成科技画面用[画面组件库](../asset/motion/README.md)，录屏和实拍用[叠加层组件](../asset/overlay/README.md)。从对应库复制 `components/` 与 `fonts/` 到工程，按组件表选组件、填参数、定时间，项目说明记录所用库和版本；缺的效果先在库里做好再用，不在单期工程里另起风格。截图举证、引文、开场结论、个人看法、日期图、时间线、章节进度条已在组件库 v3.1（evidence-shot、quote-card、summary-card、opinion-card、date-chart、timeline-lanes、units-grid、progress），优先选用。先检查代表镜头，再完成整片。录屏类按下方[产品录屏](#产品录屏)制作。
6. 字幕按[共用规范](../制作规范.md#字幕与声音)处理。所有双语字幕使用既有独立字幕压制入口。仅中文时只生成中文轨和显示层，不添加空英文占位，也不为此默认重建一套双语预设。仅中文字幕先用 `pipelines/subtitles/narration_cues.py` 从发音稿与 tighten 产出的 timing.json 生成字幕（切分规则在 subtitle-policy.json），再用 `burn_subtitles.py --zh-only` 压制；画面底部有进度条、要点文字等常驻元素时，用 `--bottom-px` 把字幕抬到它们上方，不在 HyperFrames 里另画字幕层。用法见[字幕压制说明](../pipelines/subtitles/presets/subtitle-compositing.md)。
7. 修改动画后检查工程并抽查关键帧，配音改动后同步字幕、镜头和最终导出。按共用规范听看验收；需要投稿 B站时进入 [B站发布](B站发布.md)。

## 多子代理并行

依据：AGENTS.md 工作方式（用户 2026-11-06 要求制作默认多子代理并行）。主代理拆分、派发、汇总和验收；子代理各做一块，按文件划分归属。

| 阶段 | 可以并行的块（各交一个子代理） | 必须串行或单独做的 |
| --- | --- | --- |
| 收集素材（第一步就并行） | 不同来源分头收集并整理成素材条目：官网与产品资料、新闻与评测、相关视频字幕与截帧、社区与论坛讨论、实测与录屏、各方公开说法 | 主代理把各方条目合进素材表（按时间叙事时排成时间线），逐条回原始文件核对来源、日期和原意 |
| 写稿 | 素材筛选（例如从上千条消息或长视频字幕里筛关键句）可交子代理初筛；稿件写完后交一个子代理做口语化与去 AI 味 | 稿件由主代理写；口语化稿由主代理核对事实后交用户审稿 |
| 画面预审 | 截图补拍、文字识别定位关键句、缺的组件或信息图（不同组件给不同子代理） | 拼装工程和估算时间轴由主代理做，交用户看无声预览 |
| 配音 | 无 | 本机配音同一时间只跑一个任务；配音期间可并行做画面和封面 |
| 画面与字幕 | 新组件开发、封面、字幕切分检查可并行 | 按真实时间轴重排、整片 check 由主代理做 |
| 验收 | 全片逐镜头抽帧可按章节分给多个子代理看，各报溢出、遮挡、错字 | 最终听看与发布由用户确认 |

- 收集素材的子代理统一交回素材条目，每条含：编号、日期时间（注明时区）、来源平台与位置（频道、帖子、页面、视频时间戳）、作者或发言人、原文逐字或画面描述、链接、文件路径（截图、截帧、录屏）、用途备注。引用他人原话时再加上下文核对：回复对象、是否玩笑、对方是否也有过错、当事方是否否认过。主代理按编号或日期合并，不再二次整理格式。
- 派发时写清：目标、要读的规则文件、只许改的目录、禁止改的文件、验收方式和交付格式。子代理改共用文件前先备份。
- 子代理的报告不直接当结论：主代理重跑测试或抽查真实产物，对不上就退回重做。
- 两个子代理不同时改同一个文件；需要改同一份规则文档的建议，由子代理写进报告，主代理统一落笔。

## 封面与标题先行

方法来自用户转述的影视飓风经验，不视为已独立核验的作者原话或点击效果结论。

- C1 先写点击理由：用一句话说明“谁会想看，以及他想知道什么”。落到具体困惑、反常识结果或生活收益，不能只写技术名称和功能清单。
- C2 成组构思：写稿前默认拟 3 组“标题 + 封面主体/场景 + 封面大字”，分别探索悬念、惊奇感、生活关联，可按题材组合使用。给出推荐组和理由；用户已指定方案时直接沿用。这一步先做文字构思或草图，不要求先渲染三张正式封面。候选与采用理由留在制作区，发布包只放最终采用的一组。
- C3 封面方法：优先探索“真人或冲击性场景 + 大字”。真人的表情、动作应与本期内容有关；场景优先选鲜明对比、异常尺度或直观结果。没有适合的真人素材时用场景，不为套公式强加人脸。画面只突出一个核心看点，大字提炼短语，不把完整标题或多条卖点塞进封面。
- C4 标题方法：悬念让观众想知道原因或结果；惊奇感突出有依据的反差，允许强化措辞与设问；生活关联说清对观众的时间、成本、日常困扰或实际选择有什么影响。标题仍须让人知道大致在讲什么，不能只剩“太神奇了”。封面展示看点，标题补充问题、背景或与观众的关系，避免简单重复。
- C5 内容兑现：为选中的组合记录对应的证据、演示或案例。可以暂不揭晓答案，不能编造结果、数字或用户收益。开头迅速承接封面与标题提出的问题，正文给出兑现内容；沿用首帧有内容的要求，不为悬念增加空片头。素材不足以支撑承诺时，调整标题、封面或选题，再进入全片配音与制作。
- C6 定稿复核：成片结论变化时同步修改标题与封面，按[封面和标题验收](../制作规范.md#画面与封面)检查手机缩略图、标题配合及内容兑现。项目记录目标观众、点击理由、候选组合、采用理由、兑现位置和检查结果。仅凭主观选优不宣称已验证点击率提升。

## 旁白与口播

口播沿用此前已认可的表达方式。声线认可只确定参考和处理方法，不证明新稿的读音、句尾和连续性已通过；更换声音后重新验证字幕和剪辑节奏。

### 口语化与去 AI 味（子代理）

主代理写完口播稿、交用户审稿之前，固定派一个子代理把稿子改成能直接说出口的口语，提示词见[配音稿件准备提示词](../pipelines/audio-jobs/preparation-prompts.md#本人原创旁白口语化与去-ai-味子代理)。目的是去掉书面腔和 AI 腔，不改内容。

- 改说法，不改事实：数字、日期、人名、产品名、引语原文、限制条件和结论强弱一律不变，不加新信息，不加夸张判断。
- 常见改法：补真实的承接（到了、结果、然后、所以、不过）；打散重复句式（例如每行都是“X 月，某某说”）；换掉书面词和套话（“值得一提的是”“总的来说”“进行”“不仅……更……”等）；长句拆短；必要时对听众说一句（“你算一下”）或用一次简短设问，但不每段都问，口头语气词全篇少量使用。
- 格式不变：每行一个语义单元，单句不超过 80 字，行数可增减但要说明。
- 子代理交回口语化稿和逐行对照（原句 → 新句 → 改了什么）。主代理逐行核对上面“不变”的内容，字数增加超过 15% 时说明原因并预估时长；不通过的行退回或改回原句。
- 发音稿从核对后的口语化稿生成；模型读不稳的英文名在发音稿写中文读法，见[Higgs 管线](../pipelines/tts-higgs/README.md)。

### 本人配音的口播表达调整

本人声线配音生成前默认先改写再精简。适用于可编辑的本人讲解稿；需逐字保留的引文不套用。

- E1 先按全文理清关键句的承接、对比和新信息，再写口播稿。写短句，每句话有明确的信息。主语或条件省略导致比较难跟随时补清，已经清楚的短句保留；不把每句话扩写成相同结构。
- E2 需要突出预期与结果的差异时，可用简短提问与回答，例如“那两者都给呢？还是四十七分”。只有内容确有这层关系时使用，不给每段强加问句或情绪。
- E3 从结果进入建议、从建议进入限制时，保留必要承接，如“所以”“不过”。承接须符合真实逻辑，不把相关性改成因果，也不增加事实、数字或夸张判断。
- E4 表达关系明确后再精简：删去重复结构、无必要的铺垫和结尾重复引入，保留有效的比较、提问与回答、转场和完整结论。目标是容易跟上且紧凑，不追求字数相同，也不靠整体加速压时长。
- E5 先解决说话逻辑，再设计停顿。例如“如果有这类翻译需求，维护一份术语表会大幅改善翻译效果。”把条件与收益讲成一个完整意思，不把建议孤立成突兀短句，也不靠硬插长静音补救。
- E6 结尾按完整收束设计：补充限制放在最终判断之前，最后一句落到明确选择。长句连续报数字、列举功能时，先改写语义分句，再核对换气停顿。
- E7 改写与精简由 agent 完成，脚本不会自行重写文稿。检查事实与读法一致、漏读或重复、实际时长及听感。单纯调整切分、增加静音或添加呼吸不视为已证实的表达改善。表达调整与音色配方分别维护，不因表达调整改动参考录音、EQ、音高或语速。

### 读音

- 产品名、英文缩写、数字、单位和版本号先确定读法。每期维护“正式名称 → 固定口播读法”表，画面用正式名。同一对象的口播名称保持一致，模型名称带系列、版本与规模，不在“Qwen”“9B”等含义不同的简称之间切换。改写发音不能改变所指对象。
- 常见英文产品名、平台名与缩写默认直接读英文，不自动替换为中文翻译或音译；已有明确中文读法或用户指定时优先。Qwen 固定读作“千问”，避免 Q 与 wen 拆读。数字与 B 作为一个型号片段连贯读出，发音稿不插空格，邻近数字、版本号和单位用完整语义句隔开。
- “这”读标准四声 zhè，显示稿保留汉字，发音稿需要时用 {zhe4}，效果仍须试听。
- 按语义停顿，“命令行工具”“免费开源”“窗口管理”等词组连贯读出。听到的问题记为错读、词组断开、重音不当或停顿不当；没有证据时不归因于模型内部的分词器。
- ASR 拼写差异仅作疑点，先听与独立复核，不自动改回中文。

### 整篇生成与试听

- 发音稿每行一个语义单元，每行是一次独立生成（同一参考与逐字稿，不带上一行），模型只加载一次，行间固定插入 0.8 秒静音，拼成一条连续主音轨。单行超过 80 字在句末切段；每段的生成上限是 1024 帧，触发即标记。固定模型、参考录音与参数。
- 漏句先改清楚该行并整篇重新生成，新稿用新输出目录。分行按语义边界安排，不按字数机械切分，也不把一句话拆到两行。统一响度只能处理音量，不能证明声线与语气连续。
- 短试听从主音轨截取，覆盖开头、关键术语、长句或数字、行间衔接、案例转场和完整结尾，不加音乐。新声线或独立发音实验可以先用短稿，但不能拼成正式旁白，也不为满足检查清单人为制造拼接。
- 检查原始输出，记录实际出现的问题、修正和复听结果；不以自动转写替代人工听辨。

### 句尾与节奏

- 陈述句句尾按语义收束，避免无意的疑问语气和拖长尾音；问句与尚未讲完的列举允许相应语调。不能把中文声调的自然升高一律判成异常，不用全局降调或逐字压平来修句尾。原录音习惯是否迁移到克隆输出要通过同稿对照验证。
- 句内发声速度和句间间隔分别检查。用户偏好句内利落、句间有清楚留白，避免把字均匀铺满时长。
- 配音管线不做气口压低（2026-11-07 起），气口在剪辑时处理；保留尾字与自然衰减，不做逐句硬切。不要只插静音就宣称真人感已验收。

### 本人配音的停顿检查

- 句号后停顿下限及自动检查见[本人配音入口](../pipelines/personal-voice/README.md#停顿)，不足或无法核验时先处理报告，再同步字幕、画面和导出。
- 先按语义组织逗号、句号和段落，不用连续标点或省略号堆出停顿。生成后检查句内承接、句间停顿与段落换气，避免各层级都一样长。
- 精确停顿须在已确认的完整语句边界由程序拼接或编辑，不按字数猜时间戳、不剪词尾、不把呼吸标签当定长静音。工具限制见 [Higgs 管线](../pipelines/tts-higgs/README.md)：没有毫秒停顿参数。
- 需要统一段落间距时，先测量行间拼接处词尾、自然衰减及下一句起音之间已有的留白，再按语义层级补足或缩短。普通句间与章节转场分别安排，不给所有边界机械追加相同静音。时长由当期短样听审确定，记录新增静音并重建字幕和镜头时间轴。管线只在行间插入固定 0.8 秒静音，不按语义层级调整。

## 产品录屏

适用于本人原创讲解与产品录屏，原片翻译保持原意和原结构。

- 沿录制顺序与操作含义选连续素材，不按字幕逐句切碎。保留原始完整视野、原速、原鼠标大小，不持续加标题栏、边框或额外放大。允许必要的等比画幅适配。
- 现有录屏优先；缺少演示时尽量自行录屏采集，截图补难以实录的结果。演示素材仍不足或无法采集时，才回退到更多文字说明的版本，并在项目说明记录缺失内容与回退原因。正文能直接演示时保留操作过程。
- 先设置判断标准再展示判断结果，不把不同用途的标准混在一起。
- 录屏上的叠加图形按[样式规范](../样式规范.md) Y4：等画面停稳再出，只用细线细字，不额外放大录屏。
- 运行 HyperFrames 检查与关键帧复核。

## 画面与节奏

- 开头不留空镜：首帧就有可理解的主体、问题或结论，不用纯背景、黑场、只有装饰的片头等待内容入场。旁白尽快切入；结论先行的视频，核心选择首帧可见，不等旁白念到才揭示。
- 开场验收抽查 0、0.5、1、3 秒并连续观看前 5 秒，检查是否等待内容出现。全片中段快照和技术检查通过不能代替开场与节奏验收。
- 每期原创视频固定带底部章节进度条，开场一段也算一章，进度条全片常驻（用户 2026-11-06 定）。章节名用 2–4 字短名，避免短章节标签互相挤压。
- 按时间顺序讲述的章节（发货承诺、事件经过、版本演进等），在每个截图或截帧镜头上方挂日期游标：游标随镜头移到该素材的日期，已讲过的日期留作刻度，和底部进度条一上一下。非时间顺序的章节和信息图镜头不挂。组件见[样式规范](../样式规范.md) Y7。
- 每个镜头有清楚的信息重点，截图展示正在讲的功能，文字在实际观看尺寸下可读，动画不妨碍理解。
- 整体节奏按信息单元设计：结论、证据、案例、操作和小结各有进入与结束，普通句间、案例切换、章节切换分开安排。不得把快语速、频繁切镜或平均镜头长度当作好节奏。
- 区分句内表达、句间停顿、看图理解三种时间。语音说完不代表观众已读完。新增案例先用引入句，按“看见对象 → 理解用途 → 得出判断”安排声画；复杂图片、界面和数据图留辨认与阅读时间。同一界面有连续操作时可以保持镜头，不必跟每条字幕切页。

## 学习参考

真人感参考玄离199、IT咖啡馆，学习句子组织、重音、停顿、语速变化、案例引入和声画承接，不克隆作者音色。参考作者要用实际音频分析，字幕密度不足以判断语音节奏。学习参考记录来源、时间点、观察方式与本片应用结果。逐人说话方式见[六位作者的说话方式](../模仿对象/六位作者说话方式.md)，样本、时间点与观察方法见[统一声画学习](../模仿对象/六位作者声画学习与制作规则.md)。只吸收有证据且适合对应片型的方法，不复制参考作者声线、口头禅或某条视频的固定节奏。单期认可结果不作为新片的验收结论。
