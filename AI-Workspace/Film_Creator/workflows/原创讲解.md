# 原创讲解视频

适用于 agent 根据选题、文字或资料编写旁白，并通过 HyperFrames 制作画面的视频。全局约定见 [AGENTS.md](../AGENTS.md)，共用验收见 [制作规范](../制作规范.md)。已有视频加字幕或重配音走[视频翻译](视频翻译.md)，不自动重写原片结构。

## 默认选择与项目记录

- S1 声音：本人配音视频暂定使用本地 CosyVoice3 普通版。原创讲解沿用已认可的本人声线及[CosyVoice3配方](../asset/voices/personal/personal-cosyvoice3.json)，不重复询问是否使用本人声线。用户本次指定其他声音或引擎时按要求执行，并记录选择。
- S2 字幕：每个新项目开始时询问“仅中文字幕，还是中英双语字幕？”。本次已明确或该项目已确认则沿用，不在续做、返工时重复询问。不能因为上一期选过某种语言就跳过新项目询问。
- S3 其他信息：沿用已知平台、画幅、时长和素材，只补问会影响制作的缺项。在项目说明记录这些信息、字幕选择、声线配方和发布授权范围。

## 制作顺序

1. 根据选题核验核心事实，按下方“封面与标题先行”形成候选组合并确定本期方向，记录吸引观众点击的理由和片中兑现方式，再写脚本。脚本按“结论 → 按场景展开的问题 → 证据 → 使用方法 → 限制与最终选择”展开，章节导航和段内小问题分层，观众能知道当前在回答什么。整理正式名称与口播读法，写显示稿和必要的发音稿。
2. 本人配音按下方[旁白与口播](#旁白与口播)改写稿件，整篇生成连续主旁白并截取短试听。命令与检查见[本人配音入口](../pipelines/personal-voice/README.md)，模型环境见[CosyVoice3说明](../pipelines/tts-cosyvoice3/README.md)。逐段复核不可省略，旧逐字处理坐标不能套到新音频。
3. 先审定旁白，再确定字幕和画面时间。超时优先删冗余信息，不靠整体加速把过长稿件塞进固定时长。仅中文字幕依据最终中文旁白生成。中英双语先把最终中文显示稿译为英文，按对应语义配对，两种语言均跟最终旁白时间轴对齐。
4. 制作 HyperFrames 工程前读取 hyperframes 技能及所需领域技能，使用工作区 `tools/hyperframes/run` 或已经配置的项目 scripts。先检查代表章节卡与操作镜头，再完成整片。录屏类按下方[产品录屏与章节](#产品录屏与章节)制作。
5. 字幕按[共用规范](../制作规范.md#字幕与声音)处理。所有双语字幕使用既有独立字幕压制入口。仅中文时只生成中文轨和显示层，不添加空英文占位，也不为此默认重建一套双语预设。
6. 修改动画后检查工程并抽查关键帧，配音改动后同步字幕、镜头和最终导出。按共用规范听看验收；需要投稿 B站时进入 [B站发布](B站发布.md)。

## 封面与标题先行

方法来自用户转述的影视飓风经验，不视为已独立核验的作者原话或点击效果结论。

- C1 先写点击理由：用一句话说明“谁会想看，以及他想知道什么”。落到具体困惑、反常识结果或生活收益，不能只写技术名称和功能清单。
- C2 成组构思：写稿前默认拟 3 组“标题 + 封面主体/场景 + 封面大字”，分别探索悬念、惊奇感、生活关联，可按题材组合使用。给出推荐组和理由；用户已指定方案时直接沿用。这一步先做文字构思或草图，不要求先渲染三张正式封面。候选与采用理由留在制作区，发布包只放最终采用的一组。
- C3 封面方法：优先探索“真人或冲击性场景 + 大字”。真人的表情、动作应与本期内容有关；场景优先选鲜明对比、异常尺度或直观结果。没有适合的真人素材时用场景，不为套公式强加人脸。画面只突出一个核心看点，大字提炼短语，不把完整标题或多条卖点塞进封面。
- C4 标题方法：悬念让观众想知道原因或结果；惊奇感突出有依据的反差，允许强化措辞与设问；生活关联说清对观众的时间、成本、日常困扰或实际选择有什么影响。标题仍须让人知道大致在讲什么，不能只剩“太神奇了”。封面展示看点，标题补充问题、背景或与观众的关系，避免简单重复。
- C5 内容兑现：为选中的组合记录对应的证据、演示或案例。可以暂不揭晓答案，不能编造结果、数字或用户收益。开头迅速承接封面与标题提出的问题，正文给出兑现内容；沿用首帧有内容的要求，不为悬念增加空片头。素材不足以支撑承诺时，调整标题、封面或选题，再进入全片配音与制作。
- C6 定稿复核：成片结论变化时同步修改标题与封面，按[封面和标题验收](../制作规范.md#画面与封面)检查手机缩略图、标题配合及内容兑现。项目记录目标观众、点击理由、候选组合、采用理由、兑现位置和检查结果。仅凭主观选优不宣称已验证点击率提升。

## 旁白与口播

口播沿用此前已认可的表达方式。声线认可只确定参考和处理方法，不证明新稿的读音、句尾和连续性已通过；更换声音后重新验证字幕和剪辑节奏。

### 本人配音的口播表达调整

本人声线配音生成前默认先改写再精简。适用于可编辑的本人讲解稿；需逐字保留的引文或原片译配不套用。

- E1 先按全文理清关键句的承接、对比和新信息，再写口播稿。写短句，每句话有明确的信息。主语或条件省略导致比较难跟随时补清，已经清楚的短句保留；不把每句话扩写成相同结构。
- E2 需要突出预期与结果的差异时，可用简短提问与回答，例如“那两者都给呢？还是四十七分”。只有内容确有这层关系时使用，不给每段强加问句或情绪。
- E3 从结果进入建议、从建议进入限制时，保留必要承接，如“所以”“不过”。承接须符合真实逻辑，不把相关性改成因果，也不增加事实、数字或夸张判断。
- E4 表达关系明确后再精简：删去重复结构、无必要的铺垫和结尾重复引入，保留有效的比较、提问与回答、转场和完整结论。目标是容易跟上且紧凑，不追求字数相同，也不靠整体加速压时长。
- E5 先解决说话逻辑，再设计停顿。例如“如果有这类翻译需求，维护一份术语表会大幅改善翻译效果。”把条件与收益讲成一个完整意思，不把建议孤立成突兀短句，也不靠硬插长静音补救。
- E6 结尾按完整收束设计：补充限制放在最终判断之前，最后一句落到明确选择。长句连续报数字、列举功能时，先改写语义分句，再核对换气停顿。
- E7 改写与精简由 agent 完成，脚本不会自行重写文稿。检查事实与读法一致、漏读或重复、实际时长及听感。单纯调整切分、增加静音或添加呼吸不视为已证实的表达改善。表达调整与音色配方分别维护，不因表达调整改动参考录音、EQ、音高或语速。

### 读音

- 产品名、英文缩写、数字、单位和版本号先确定读法。每期维护“正式名称 → 固定口播读法”表，画面用正式名。同一对象的口播名称保持一致，模型名称带系列、版本与规模，不在“Qwen”“9B”等含义不同的简称之间切换。改写发音不能改变所指对象。
- 常见英文产品名、平台名与缩写默认直接读英文，不自动替换为中文翻译或音译；已有明确中文读法或用户指定时优先。Qwen 固定读作“千问”，避免 Q 与 wen 拆读。数字与 B 作为一个型号片段连贯读出，发音稿不插空格，邻近数字、版本号和单位用完整语义句隔开。
- “这”读标准四声 zhè，显示稿保留汉字，发音稿需要时用 {zhe4}，效果仍须试听。
- 按语义停顿，“命令行工具”“免费开源”“窗口管理”等词组连贯读出。听到的问题记为错读、词组断开、重音不当或停顿不当；没有证据时不归因于模型内部的分词器。
- ASR 拼写差异仅作疑点，先听与独立复核，不自动改回中文。

### 整篇生成与试听

- 定稿全文一次提交生成，保留一条连续主音轨。本地 CosyVoice3 仍会在内部按标点与长度分组，整篇提交不等于无内部分组，记录实际分组数。固定模型、参考录音与参数。
- 漏句先改清楚句子并整篇重新生成。修订优先使用连续语义范围，避免逐句独立生成；只有长稿失败或局部修订确有需要时才分段，并记录原因和边界。统一响度只能处理音量，不能证明声线与语气连续。
- 短试听从主音轨截取，覆盖开头、关键术语、长句或数字、模型内部组衔接、案例转场和完整结尾，不加音乐。新声线或独立发音实验可以先用短稿，但不能拼成正式旁白，也不为满足检查清单人为制造拼接。
- 检查原始输出，记录实际出现的问题、修正和复听结果；不以自动转写替代人工听辨。

### 句尾与节奏

- 陈述句句尾按语义收束，避免无意的疑问语气和拖长尾音；问句与尚未讲完的列举允许相应语调。不能把中文声调的自然升高一律判成异常，不用全局降调或逐字压平来修句尾。原录音习惯是否迁移到克隆输出要通过同稿对照验证。
- 句内发声速度和句间间隔分别检查。用户偏好句内利落、句间有清楚留白，避免把字均匀铺满时长。
- 句尾咂嘴与多余气口应检查，只减弱可与字音分开的杂音，保留尾字、自然衰减与必要呼吸，不做逐句硬切。不要只插静音就宣称真人感已验收。

### 本人配音的停顿检查

- 句号后停顿下限及自动检查见[本人配音入口](../pipelines/personal-voice/README.md#停顿)，不足或无法核验时先处理报告，再同步字幕、画面和导出。
- 先按语义组织逗号、句号和段落，不用连续标点或省略号堆出停顿。生成后检查句内承接、句间停顿与段落换气，避免各层级都一样长。
- 精确停顿须在已确认的完整语句边界由程序拼接或编辑，不按字数猜时间戳、不剪词尾、不把呼吸标签当定长静音。工具限制见[停顿控制核验](../pipelines/personal-voice/pause-control.md)。
- 需要统一段落间距时，先测量模型内部组与拼接处词尾、自然衰减及下一句起音之间已有的留白，再按语义层级补足或缩短。普通句间与章节转场分别安排，不给所有边界机械追加相同静音。时长由当期短样听审确定，记录新增静音并重建字幕和镜头时间轴。管线不会自动执行这一处理。

## 产品录屏与章节

适用于本人原创讲解与产品录屏，原片译配保持原意和原结构。

- 沿录制顺序与操作含义选连续素材，不按字幕逐句切碎。保留原始完整视野、原速、原鼠标大小，不持续加标题栏、边框或额外放大。允许必要的等比画幅适配。
- 现有录屏优先；缺少演示时尽量自行录屏采集，截图补难以实录的结果。演示素材仍不足或无法采集时，才回退到更多文字说明的版本，并在项目说明记录缺失内容与回退原因。正文能直接演示时保留操作过程。
- 主章节与小节分层，使用一致的标题、说明、编号、位置导航及进入／退出动画，留阅读时间再回到完整演示。章节名称按本期内容选择。
- 先设置判断标准再展示判断结果，不把不同用途的标准混在一起。
- 运行结构检查、HyperFrames 检查与关键帧复核。

## 画面与节奏

- 开头不留空镜：首帧就有可理解的主体、问题或结论，不用纯背景、黑场、只有装饰的片头等待内容入场。旁白尽快切入；结论先行的视频，核心选择首帧可见，不等旁白念到才揭示。
- 开场验收抽查 0、0.5、1、3 秒并连续观看前 5 秒，检查是否等待内容出现。全片中段快照和技术检查通过不能代替开场与节奏验收。
- 每个镜头有清楚的信息重点，截图展示正在讲的功能，文字在实际观看尺寸下可读，动画不妨碍理解。
- 整体节奏按信息单元设计：结论、证据、案例、操作和小结各有进入与结束，普通句间、案例切换、章节切换分开安排。不得把快语速、频繁切镜或平均镜头长度当作好节奏。
- 区分句内表达、句间停顿、看图理解三种时间。语音说完不代表观众已读完。新增案例先用引入句，按“看见对象 → 理解用途 → 得出判断”安排声画；复杂图片、界面和数据图留辨认与阅读时间。同一界面有连续操作时可以保持镜头，不必跟每条字幕切页。

## 学习参考

真人感参考玄离199、IT咖啡馆，学习句子组织、重音、停顿、语速变化、案例引入和声画承接，不克隆作者音色。参考作者要用实际音频分析，字幕密度不足以判断语音节奏。学习参考记录来源、时间点、观察方式与本片应用结果。声音与表达研究入口见[学习路线](../模仿对象/声线与说话方式学习路线.md)，样本、时间点与观察方法见[统一声画学习](../模仿对象/六位作者声画学习与制作规则.md)。研究优先级不代表已更换配音管线。只吸收有证据且适合对应片型的方法，不复制参考作者声线、口头禅或某条视频的固定节奏。单期认可结果不作为新片的验收结论。
