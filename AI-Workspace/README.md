# AI-Workspace

一份从我的日常工作区提取的目录与管理约定，主要面向 macOS。拿到后，把这个目录交给 AI，让它沿用这里的技术选型和文件分工，检查本机条件，按实际任务补齐工具。

这里保留工程规则、制作偏好、共用技能管理方式和有用的路径布局。源码项目、个人想法、现有技能正文、模型及已安装环境不随包提供。目录出现不代表工具已经安装，也不代表某个 AI 已经加载了这里的规则。

## 目录分工

```text
AI-Workspace/
├── 想法储备-真人管理/     留给本人管理的想法，初始为空
├── Code_Projects/        软件项目与工程约定
│   ├── AGENTS.md
│   └── CLAUDE.md
├── Film_Creator/         视频、配音、转写与说话人分段
│   ├── AGENTS.md
│   ├── CLAUDE.md
│   ├── 制作规范.md
│   ├── projects/        每期项目、目录索引与交付状态
│   ├── pipelines/       每条管线的模型、环境与运行入口
│   ├── tools/           共享制作工具
│   └── 模仿对象/        参考来源、拆解与学习记录
└── Skill_Share/          共用技能的统一源文件
    ├── AGENTS.md
    └── CLAUDE.md
```

Git 不保存空目录，因此空目录里仅放 `.gitkeep` 占位文件。`想法储备-真人管理/` 不包含任何个人想法或管理规则，内容由使用者自己决定。

## 开始使用

把 `AI-Workspace/` 复制到自己的工作位置，例如 `~/Documents/AI-Workspace/`。也可以将四个工作目录分别放到 `~/Documents/`，与我的本地布局一致。已有同名目录时先比较内容，不整目录覆盖。

在 AI 工具中打开要使用的目录，让它先读该目录的 `AGENTS.md`；`CLAUDE.md` 只负责指向同一份正文。可直接发送：

> 请先阅读这个工作目录的 AGENTS.md 和相关说明。我想用它完成【具体任务】。核对本机系统、已有工具及实际路径，沿用文档中的技术选型和目录分工，只补齐本次任务缺少的依赖。先说明安装位置和需要的权限，不覆盖已有配置。完成后运行最小验证，把实际版本、运行入口、结果和未解决项写入对应项目或管线说明。不要因为目录已经存在就认为环境已安装。

工具按任务补齐。写代码时沿用目标仓库的语言、包管理器和锁文件。视频制作参考本地 Qwen3-TTS、Whisper、SpeakerKit、FFmpeg 与 HyperFrames 的分工，具体布局见 [制作约定](Film_Creator/AGENTS.md)。这些管线和技能的安装包、运行脚本不在本分享包内，AI 需要核对来源后建立并验证入口。其他系统可以沿用管理方式，但 macOS 的系统能力和 Core ML 管线需要单独评估适配。

## 长期开发如何留下记忆

源码和本地笔记并排放，示例如下，使用时才创建：

```text
Code_Projects/
├── example/                         源码仓库，可重新克隆
└── example-notes/                    本地经验，清理源码时保留
    ├── README.md                    仓库、源码位置、核对日期与笔记入口
    ├── example-local-dev.md         本机环境、构建、运行与验证
    └── example-todo.md              待办、取舍、明确不做及其理由
```

源码里的开发文档与 GitHub issue/PR 仍是各自内容的事实来源，笔记用链接引用，不再复制维护另一份状态。长任务的活账本放在 todo 文件，桌面保留入口；供本人直接验证的构建产物与测试文件仍交付到桌面。完整规则见 [工程约定](Code_Projects/AGENTS.md)。

共用技能先在 `Skill_Share/<skill-name>/` 更新，修改前在技能自己的 `archive/` 归档，再同步到 AI 工具的启用目录。此处只分享管理说明，技能由使用者自行选择。详见 [技能管理约定](Skill_Share/AGENTS.md)。

## 本机差异

`tools/python`、`~/.local/share/uv/python` 等路径保留了我的环境组织方式，使用前要核对实际位置。文档中的声线、制作规范和工程取舍是可调整的个人偏好。

Code_Projects 中程序坞的 computer-use 条目记录了一次本机观察，带有系统版本与日期。其他机器先复现相同症状再采用，不把隐藏程序坞变成通用前置步骤。首次采用时也应检查桌面交付位置、发布授权和各 AI 工具的技能目录是否符合自己的习惯。
